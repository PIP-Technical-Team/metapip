# Review Report: Resilient Networking & Time

**Review mode**: standard (auto-routed by `/cg-work review:auto`)
**Files reviewed**: R/package_branches.R, R/get_branches.R, R/core_metadata.R, DESCRIPTION, NEWS.md, man/get_current_branches.Rd, tests/testthat/*.R, .cg-docs state files
**Findings**: 17 total (P0: 1, P1: 4, P2: 7, P3: 5)

## P0 — BLOCKING

### [P0.1] cg-data-quality R/package_branches.R:138-149 — NA PROD version masks PROD comparison
**Why**: If the PROD branch's DESCRIPTION fails to fetch, `dev` gets `branch = "PROD", version = NA`, and `join_and_get_status()`'s `fcase` has no `is.na(version)` guard before `fselect(-branch, -version)` drops it. A package would be reported "up-to-date" relative to an *unknown* PROD version.
**Fix**: Add `is.na(version), paste(branch_to_compare, "version unknown")` to the `fcase` before `default`, and warn on NA compared-branch versions.

## P1 — CRITICAL

### [P1.1] cg-testing / cg-reproducibility tests/testthat/test-get_branches.R:66-159, test-core_metadata.R:8-30 — new tests not hermetic (depend on local git credentials)
**Why**: The new `get_latest_branch_update()`/`core_metadata()` tests stub internal functions but not `check_github_token()`, which calls `gitcreds::gitcreds_get()`. On a clean CI machine without stored creds it aborts before the stubs run. Contradicts the plan's C4 hermetic/no-live-network constraint.
**Fix**: Stub `check_github_token` in affected tests: `mockery::stub(get_latest_branch_update, "check_github_token", function() list())` and `mockery::stub(core_metadata, "check_github_token", function() list())`.

### [P1.2] cg-data-quality / cg-reproducibility tests/testthat/test-core_metadata.R:1-6 — legacy live-network core_metadata test
**Why**: The pre-existing test calls `core_metadata()` with real `gh::gh()` calls (~25+ live API requests) and no skip guard. Fails hard without network/token, emits time-varying data.
**Fix**: Guard with `skip("avoid live network")` (repo convention) or mock the network sources like the added UTC test.

### [P1.3] cg-data-quality R/package_branches.R:141-147 — join_and_get_status() non-functional (fcase not in namespace)
**Why**: `fcase` is not exported by collapse and not imported; NAMESPACE imports only collapse (except=fdroplevels), glue, utils. Every `package_branches()` status call errors here. Also `local_status` is never generated by `collapse::join`. Pre-existing crash the new graceful-NA path funnels into.
**Fix**: Add `data.table` to Imports and import `fcase`, or rewrite status computation with `collapse::join(..., column = "local_status")` / base ifelse; define status semantics explicitly; include the P0.1 NA guard.

### [P1.4] cg-reproducibility / cg-architecture R/package_branches.R:71-90 — fixed 10s timeout, no retry, silent error→NA
**Why**: Transient network stall silently converts reachable branch version to NA (indistinguishable from 404), flows into downstream tables; timeout not configurable.
**Fix**: Configurable timeout (e.g. `getOption("metapip.http_timeout", 10)`), small retry with backoff, distinguish timeout/5xx (warn) from genuine 404 (unambiguous NA).

## P2 — IMPORTANT

### [P2.1] cg-code-quality R/package_branches.R:80-82 — textConnection + on.exit leak-prone pattern unnecessary
**Why**: `read.dcf()` accepts `text =`, so the transient connection and on.exit cleanup are avoidable.
**Fix**: `mat <- read.dcf(text = httr2::resp_body_string(resp))`.
**Fix** (P2.2 duplicate note): catch typed condition, prioritize Version field, suppress DCF warnings.

### [P2.2] cg-code-quality R/package_branches.R:77-89 — blanket tryCatch + unreachable status check; swallows programming errors and DCF warnings
**Why**: `req_perform()` errors on 4xx/5xx by default; the `resp_status != 200L` branch is near-dead. Blanket `error=NA` masks typos. `read.dcf()` emits warnings (not errors) on malformed DCF that the current error handler doesn't catch.
**Fix**: Use typed condition handling (`httr2_http_404`), `suppressWarnings(read.dcf(text=...))`, optionally `req_retry`.

### [P2.3] cg-documentation R/get_branches.R:103-111 + man/get_latest_branch_update.Rd — gh-pages-only behavior undocumented
**Why**: Public exported function's new edge case (warning + NA single-row frame) not documented; man page not regenerated.
**Fix**: Document in @description/@return and regenerate man page.

### [P2.4] cg-version-control — working tree mixes 5+ logical units into one uncommitted blob
**Why**: httr2 refactor, UTC timestamps, empty-branch guard, unrelated test-attach fix, unrelated Rd regeneration, knowledge-capture state all uncommitted together.
**Fix**: Commit in focused units following type(scope) convention; at minimum isolate test-attach.R and man/get_current_branches.Rd into own commits.

### [P2.5] cg-version-control / cg-reproducibility DESCRIPTION — httr2 no minimum version; tests require >= 1.0.0
**Why**: `with_mocked_responses()` requires httr2 >= 1.0.0; bare `httr2` in Imports has no floor.
**Fix**: `Imports: httr2 (>= 1.0.0)`.

### [P2.6] cg-data-quality R/package_branches.R:122-127 — common_data() hard-fails when no package has a PROD row
**Why**: `colorder(package, PROD)` errors if no PROD row present (e.g., only-gh-pages packages).
**Fix**: `colorder(package, intersect(c("PROD","DEV_v2","QA"), names(data)))` or guard.

### [P2.7] cg-data-quality R/package_branches.R:113-135 — packages with zero rows silently disappear from summary
**Why**: `split_packages_into_list()`'s `split(~package)` drops empty packages; no placeholder/warning.
**Fix**: Left-expand from requested `package`, fill NA, warn when a package yields no data.
